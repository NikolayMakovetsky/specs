## 🎯 О проекте

**TTM Lite** — это упрощённая версия системы Trouble Ticket Management (TTM), разработанная на основе анализа реальной телеком-системы. Проект демонстрирует ключевые компетенции системного аналитика:

- ✅ **Моделирование бизнес-процессов** в BPMN 2.0 (Camunda)
- ✅ **Проектирование структуры данных** для сложной предметной области
- ✅ **Настройка бизнес-правил** и маршрутизации на основе контекста
- ✅ **Разработка REST API** с документацией
- ✅ **Системный подход** к анализу и автоматизации процессов

### 📖 Бизнес-контекст

В телеком-компаниях существует стандартный процесс обработки инцидентов клиентов:

1. **Создание инцидента** — клиент сообщает о проблеме (отсутствие интернета, проблемы с VPN, качество связи)
2. **Диагностика** — специалист 1-й линии (1LTP) проводит первичную проверку
3. **Решение** — при сложности проблема передаётся на 2-ю линию (2LTP) или в профильные подразделения
4. **Подтверждение** — клиент подтверждает устранение проблемы
5. **Закрытие** — инцидент закрывается с фиксацией результата

---

## 📊 Бизнес-процесс
```
[Создание инцидента]
↓
[Диагностика 1LTP]
↓
[Выбор маршрута (Gateway)]
    │
    ├──→ [Решение МРФ]
    ├──→ [Решение 2LTP]
    └──→ [Подтверждение клиента]
↓ 
[Инцидент закрыт]

```


### 🔄 Правила маршрутизации (Rules)

Переход между заданиями определяется **контекстом инцидента**:

| Rule ID | Название | Условия | Целевое задание |
|---------|----------|---------|-----------------|
| 14525 | Требуется проверка МРФ | macro_segment=B2B, service_type=VPN L2/L3, segment=3K | Решение МРФ |
| 14526 | Передать на 2LTP | macro_segment=B2G | Решение 2LTP |
| 14527 | Проблема устранена | (нет условий) | Подтверждение клиента |
| 14528 | Запрос в ГЭП | service_type=Интернет | Проверка |
| 14529 | Недозвон до клиента | (нет условий) | Снова диагностика |

> 📌 **Принцип работы**: пользователь видит только те правила, которые соответствуют контексту его тикета.

## 🧪 Тестирование

Проект поддерживает несколько способов тестирования API:

| Способ | Инструмент | Описание |
|--------|------------|----------|
| **Ручной (Web)** | Браузер (`http://localhost:8081`) | Тестирование через визуальный интерфейс: создание инцидентов, просмотр заданий и правил |
| **Автоматический** | `test-api-auto.bat` | Быстрый запуск всех запросов через командную строку |
| **Визуальный** | REST Client (VS Code) | Тестирование API прямо в редакторе кода |
| **Профессиональный** | Postman | Полноценный API-клиент с коллекциями и переменными |
| **Ручной (CLI)** | `curl` | Для скриптов, автоматизации и быстрых проверок |


### 🔍 Ручное тестирование через Web-интерфейс

1. **Создание инцидента**
   - Заполните форму на главной странице
   - Нажмите "Создать инцидент"
   - Проверьте появление записи в таблице

2. **Проверка заданий**
   - После создания инцидента должно появиться задание "Диагностика"
   - Проверьте раздел "Задания"

3. **Проверка правил**
   - Скопируйте ID задания из раздела "Задания"
   - Вставьте в поле "ID задания" и нажмите "Показать правила"
   - Убедитесь, что отображаются правила, соответствующие контексту

### 🖥️ Визуальное тестирование через REST Client (VS Code)

**Установка**
1. Откройте VS Code (Ctrl+Shift+X)
2. Найдите расширение REST Client (от Huachao Mao)
3. Нажмите Install

**Использование**
В проекте есть файл test-api.http со всеми запросами:

```
### 1. Создать инцидент
POST http://localhost:8081/api/incidents
Content-Type: application/json

{
    "clientName": "Тестовый клиент",
    "serviceType": "Интернет",
    "problemType": "Клиентская",
    "macroSegment": "B2B",
    "address": "г. Москва, ул. Тестовая, д. 1"
}

### 2. Получить список инцидентов
GET http://localhost:8081/api/incidents

### 3. Получить список заданий
GET http://localhost:8081/api/tasks

### 4. Получить правила для задания
GET http://localhost:8081/api/tasks/{{taskId}}/rules

### 5. Завершить задание
POST http://localhost:8081/api/tasks/{{taskId}}/complete
Content-Type: application/json

{
    "ruleId": 14527,
    "comment": "Проблема решена"
}
```
**Как использовать:**

1. Откройте файл test-api.http в VS Code
2. Над каждым запросом появится кнопка Send Request
3. Нажмите на неё — ответ откроется в соседней вкладке

### 🧪 Ручное CLI тестирование

```bash
# 1. Создать инцидент
curl -X POST http://localhost:8081/api/incidents \
  -H "Content-Type: application/json" \
  -d '{
    "clientName": "Тестовый клиент",
    "serviceType": "Интернет",
    "problemType": "Клиентская",
    "macroSegment": "B2B",
    "address": "г. Москва, ул. Тестовая, д. 1"
  }'

# 2. Получить список инцидентов
curl http://localhost:8081/api/incidents

# 3. Получить задания
curl http://localhost:8081/api/tasks

# 4. Получить правила для задания (подставьте реальный taskId)
curl http://localhost:8081/api/tasks/TASK-xxx/rules

# 5. Завершить задание (подставьте реальный taskId и ruleId)
curl -X POST http://localhost:8081/api/tasks/TASK-xxx/complete \
  -H "Content-Type: application/json" \
  -d '{"ruleId": 14527, "comment": "Проблема решена"}'
```
