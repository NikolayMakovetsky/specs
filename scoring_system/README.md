
# Система кредитного скоринга

> Пет-проект по системному анализу: event-driven система автоматического и ручного одобрения заявок на кредит.

---

## 📌 О проекте

**Система кредитного скоринга** — пет-проект, демонстрирующий полный цикл работы системного аналитика: от контекстной диаграммы и ТЗ до BPMN-процесса, модели данных, REST API и схемы событий Kafka.

Проект имитирует реальный банковский процесс: заявка на кредит поступает в систему, проходит скоринг по формализованным правилам, проверки во внешних системах (БКИ, антифрод, ПОД) и либо одобряется автоматически, либо уходит на ручное рассмотрение кредитному менеджеру. При одобрении формируются график платежей и договор.

### 🎯 Цели проекта

- Продемонстрировать навыки формализации бизнес-процессов (BPMN, DFD/C4, Use Case).
- Показать работу с event-driven архитектурой (Kafka).
- Показать владение скоринговыми моделями и правилами принятия решений.
- Отразить понимание регуляторных требований (218-ФЗ, 115-ФЗ).
- Собрать портфолио артефактов системного аналитика.

### 🚧 Границы проекта (scope)

**Входит в проект:**
- Приём и валидация заявки на кредит.
- Скоринг по формализованным правилам.
- Интеграция с внешними системами: БКИ, антифрод, ПОД.
- Автоматическое и ручное принятие решения.
- Формирование графика платежей и договора.
- Публикация событий в Kafka (`credit-requests`, `scoring-results`, `loan-contracts`).

**Не входит в проект:**
- Бухгалтерский учёт выданных кредитов (АБС).
- Платёжный процессинг и обслуживание кредита.
- Маркетинговые кампании и CRM-функции.
- Коллекторская деятельность.

## 🗺️ Контекстная диаграмма

[Контекстная диаграмма](diagrams/Context_diag.png) фиксирует границы системы и внешних акторов, с которыми она взаимодействует. Выполнена в нотации **C4 Context / DFD Level 0**.


**Внешние акторы:**

| Актор | Тип | Назначение |
|---|---|---|
| Заёмщик (клиент) | Человек | Подаёт заявку, получает решение, договор и график платежей |
| Кредитный менеджер | Человек | Принимает ручные решения по заявкам, требующим рассмотрения |
| Андеррайтер (риск-аналитик) | Человек | Настраивает скоринговые правила и справочники, получает отчёты |
| Бюро кредитных историй (БКИ) | Внешняя система | Предоставляет кредитную историю и скоринговый балл |
| Антифрод-система | Внешняя система | Проверяет заявку на признаки мошенничества |
| ПОД-система | Внешняя система | Проверка по спискам 115-ФЗ (противодействие отмыванию денег) |

> 💡 **Примечание.** Kafka не показана на контекстной диаграмме, так как является интеграционной шиной (транспортом), а не внешним актором. Она будет отражена на C4 Container Diagram и диаграммах последовательности.

## 🏗️ Планируемая архитектура

> Раздел будет заполнен после проектирования C4 Container Diagram и схемы Kafka.

**Ключевые компоненты (предварительно):**
- **API Gateway / REST API** — приём заявок, статус, график платежей.
- **Скоринговый сервис** — применение правил, расчёт балла.
- **Сервис принятия решений** — авто/ручное решение.
- **Сервис договоров** — формирование графика и договора.
- **Kafka** — события: `credit-requests`, `scoring-results`, `loan-contracts`.
- **БД** — заявки, клиенты, продукты, график платежей.
