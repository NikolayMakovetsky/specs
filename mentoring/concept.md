## 1. Бизнес-контекст

### 1.1. Проблема

В крупных компаниях процесс адаптации и развития новых сотрудников часто происходит хаотично:
- Отсутствует единая база менторов и их компетенций
- Назначение ментора происходит "в ручном режиме" (через email или устные договорённости)
- Нет отслеживания прогресса менторских пар
- Результаты менторства не фиксируются и не анализируются
- Потеря корпоративных знаний при уходе опытных сотрудников

### 1.2. Целевая аудитория

| Роль | Описание | Потребности |
|------|----------|-------------|
| **HR-менеджер** | Администрирует программу менторства | Контроль процесса, назначение пар, отчётность |
| **Ментор** | Опытный сотрудник, передающий знания | Управление подопечными, фиксация встреч, материалы |
| **Менти (ученик)** | Новый или развивающийся сотрудник | Поиск ментора, отслеживание прогресса, обратная связь |
| **Руководитель** | Управляет развитием своих подчинённых | Видеть прогресс, оценивать эффективность программы |

### 1.3. Бизнес-ценность

- 📈 **Сокращение времени адаптации** новых сотрудников на 20-30%
- 🧠 **Снижение риска ухода знаний** при увольнении ключевых специалистов
- 🎯 **Повышение вовлечённости** и лояльности сотрудников
- 📊 **Прозрачность инвестиций** в развитие персонала

## 2. Цели и задачи проекта

### 2.1. Бизнес-цели

| № | Цель | Измеримый результат |
|---|------|---------------------|
| 1 | Внедрить процессную модель менторства | Все менторские пары назначены через систему, а не вручную |
| 2 | Обеспечить прозрачность | Прогресс каждой пары виден HR и руководителям в дашборде |
| 3 | Автоматизировать рутину | Напоминания о встречах, автоматическое создание отчётов |

### 2.2. Функциональные возможности (MVP)

| № | Возможность | Описание |
|---|-------------|----------|
| 1 | **Регистрация в программе** | Сотрудник может подать заявку на участие (как ментор или менти) |
| 2 | **Подбор ментора** | Автоматический/ручной подбор на основе компетенций, отдела, опыта |
| 3 | **План развития** | Ментор и менти создают совместный план на период менторства |
| 4 | **Встречи и заметки** | Фиксация проведённых встреч, темы, заметки ментора |
| 5 | **Обратная связь** | Сбор отзывов от менти, ментора и руководителя |
| 6 | **Дашборды** | Визуализация статистики по программе менторства |

## 3. Границы проекта (Scope)

### ✅ **Входит в MVP:**
- Подача заявок на участие в программе
- Профили менторов с компетенциями
- Автоматические рекомендации по подбору (алгоритм простого сопоставления)
- Создание плана развития (roadmap) на период менторства
- Журнал встреч с заметками
- Анкеты обратной связи (три уровня: менти → ментор, ментор → менти, руководитель → пара)
- Дашборд для HR с основными метриками
- Уведомления о предстоящих встречах

### ❌ **Не входит в MVP:**
- Интеграция с внешними LMS (системами обучения)
- Видео- или аудиозапись встреч
- Геймификация (достижения, рейтинги) — можно добавить в следующей версии
- Мобильное приложение (только веб-интерфейс)

## 4. Ключевые бизнес-процессы

### 4.1. Основной процесс: "Проведение менторской программы"

Сотрудник регистрируется в системе →

Заполняет профиль (компетенции, цели) →

Система предлагает ментора (или HR назначает вручную) →

Ментор подтверждает участие →

Составляется план развития →

Проводятся регулярные встречи (фиксация в системе) →

Периодическая обратная связь →

Завершение программы с итоговым отчётом



### 4.2. Дополнительные процессы
- **Управление компетенциями**: администратор создаёт/редактирует справочник навыков
- **Отчётность**: формирование сводных данных по программе
- **Архивация**: хранение истории менторства для анализа

## 6. Макет страниц (Figma)

Планируемые экраны для прототипирования:

| Страница | Описание | Ключевые элементы |
|----------|----------|-------------------|
| **Дашборд HR** | Главная страница для HR-менеджера | Статистика (всего пар, активных, завершённых), список последних активностей, график динамики |

## 7. Модель данных (предварительная)

### Ключевые сущности:

User (сотрудник) {
  id, name, email, department, position, join_date
  is_mentor, is_mentee, is_admin
}

MentorProfile (профиль ментора) {
  id, user_id, experience_years, max_mentees
  rating, is_active
}

Competency (компетенция) {
  id, name, category, description
}

MentorCompetency (связь ментора с компетенциями) {
  mentor_profile_id, competency_id, proficiency_level (1-5)
}

MentoringPair (менторская пара) {
  id, mentor_id, mentee_id, start_date, end_date
  status (pending, active, completed, cancelled)
  created_by (HR)
}

MentoringPlan (план развития) {
  id, pair_id, title, description, created_at
}

PlanTask (задача/этап плана) {
  id, plan_id, title, description, due_date
  status (planned, in_progress, done, overdue)
}

Meeting (встреча) {
  id, pair_id, scheduled_date, duration
  topic, notes, status (planned, held, missed)
  created_by (mentor or mentee)
}

Feedback (обратная связь) {
  id, pair_id, from_user_id, to_user_id
  type (mentor_to_mentee, mentee_to_mentor, manager_to_pair)
  rating, comment, created_at
}

Notification (уведомление) {
  id, user_id, type, title, message, is_read
  created_at
}

## 9. Критерии успеха проекта

| № | Критерий | Способ измерения |
|---|----------|------------------|
| 1 | 80% новых сотрудников имеют назначенного ментора в течение 2 недель | Отчёт по парам |
| 2 | 70% менторских пар проводят минимум 2 встречи в месяц | Журнал встреч |
| 3 | 85% участников довольны программой (оценка 4+/5) | Анкеты обратной связи |
| 4 | Время на административное управление программой сокращено на 60% | Сравнение с ручным процессом |
