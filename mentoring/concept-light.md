## 1. Бизнес-контекст

### Проблема

В компании нет единой базы менторов, назначение происходит хаотично, прогресс не отслеживается.

### Целевая аудитория

| Роль | Описание |
|------|----------|
| **HR** | Управляет программой менторства |
| **Ментор** | Опытный сотрудник, передающий знания |
| **Менти** | Новый сотрудник, которому нужен наставник |

## 2. Цели и задачи

| № | Цель | Измеримый результат |
|---|------|---------------------|
| 1 | Автоматизировать подбор менторов | Система предлагает ментора по компетенциям |
| 2 | Отслеживать прогресс | Журнал встреч и обратная связь |
| 3 | Сделать программу прозрачной | Дашборд для HR со статистикой |

## 3. Границы проекта (MVP)

### ✅ Входит в MVP

- Регистрация в программе (как ментор или менти)
- Профиль ментора с указанием компетенций
- Подбор ментора (автоматический + ручной)
- Журнал встреч (дата, тема, заметки)
- Обратная связь (оценка + комментарий)
- Дашборд HR (статистика по парам)

### ❌ Не входит в MVP

- План развития (roadmap) — убираем для упрощения
- Геймификация, LMS-интеграция, мобильное приложение
- Автоматические уведомления

## 4. Ключевой бизнес-процесс

1. Сотрудник регистрируется → 
2. Заполняет профиль → 
3. Система подбирает ментора → 
4. Ментор подтверждает → 
5. Встречи фиксируются в журнале → 
6. Сбор обратной связи → 
7. Завершение программы

## 6. Модель данных (5 сущностей)

```sql
-- Сотрудник
User (
  id UUID PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100) UNIQUE,
  department VARCHAR(50),
  is_mentor BOOLEAN DEFAULT FALSE,
  is_mentee BOOLEAN DEFAULT FALSE
)

-- Профиль ментора
MentorProfile (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES User(id),
  experience_years INT,
  rating DECIMAL(3,2) DEFAULT 0
)

-- Компетенция
Competency (
  id UUID PRIMARY KEY,
  name VARCHAR(50),
  category VARCHAR(50)
)

-- Связь ментора с компетенциями
MentorCompetency (
  mentor_id UUID REFERENCES MentorProfile(id),
  competency_id UUID REFERENCES Competency(id),
  level INT CHECK (level BETWEEN 1 AND 5),
  PRIMARY KEY (mentor_id, competency_id)
)

-- Менторская пара
MentoringPair (
  id UUID PRIMARY KEY,
  mentor_id UUID REFERENCES MentorProfile(id),
  mentee_id UUID REFERENCES User(id),
  status VARCHAR(20) CHECK (status IN ('pending', 'active', 'completed', 'cancelled')),
  start_date DATE,
  end_date DATE
)

-- Встреча
Meeting (
  id UUID PRIMARY KEY,
  pair_id UUID REFERENCES MentoringPair(id),
  date DATE,
  topic VARCHAR(200),
  notes TEXT
)

-- Обратная связь
Feedback (
  id UUID PRIMARY KEY,
  pair_id UUID REFERENCES MentoringPair(id),
  from_user_id UUID REFERENCES User(id),
  rating INT CHECK (rating BETWEEN 1 AND 5),
  comment TEXT,
  created_at TIMESTAMP DEFAULT NOW()
)
```

### ER-схема (логическая)

```
User ──┬── MentorProfile ──┬── MentorCompetency ──┬── Competency
       │                   │
       └── MentoringPair ──┼── Meeting
                           │
                           └── Feedback
```

## 8. Критерии успеха

| № | Критерий | Способ измерения |
|---|----------|------------------|
| 1 | 80% новых сотрудников получают ментора за 2 недели | Отчёт по парам |
| 2 | 70% пар проводят ≥2 встреч в месяц | Журнал встреч |
| 3 | 85% участников оценивают программу на 4+ | Анкеты обратной связи |
